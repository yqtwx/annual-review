# 用量、投入与个人年度画像

## Token 总量与峰值日

统计真实 provider usage；不使用文本长度估算、不将上下文当前占用当成累计消耗、不把相同累计快照反复相加。标明输入 + 输出、缓存输入是否已包含、推理输出是否属于输出的子集、来源与截止时刻。自动审核与协作用量单列；是否进入年度总量需写清。只有可核验记录时标题用「可核验年度用量」，不能写成跨账户全部账单，更不能从 token 推算成本、工时或努力程度。

Codex 的 `token_count.info.total_token_usage` 是累计值，按同一会话正增量求和；相同快照贡献零。重置时使用当次 `last_token_usage`，并记录重置；字段不一致或无法定位的部分单独列为缺口。fork / 子代理日志可含父会话的历史：使用实际元数据确认自己的记录与继承边界，仅计算新产生的响应，归入原项目。Guardian / auto-review 不属于用户选择的常用模型。

WorkBuddy 支持日志的 `providerData.usage / rawUsage`，按来源命名空间 + 模型响应 `messageId` 去重。一个 conversationRequestId 可含许多模型调用，不能用它合并全部用量。相同响应在多个工具事件出现只记一次；不同响应有相同用量也不能合并。`session_usage.used/size` 可能是当前上下文占用，不作累计用量。

把有效用量的完成时间转换到用户时区后归入日期。峰值日附当天各项目贡献，核对贡献之和等于当天总量。跨午夜长任务若只有最终 usage 时间，注明按响应完成日计，不推断实际每分钟耗用。

## 最晚使用

仅以人类消息、附件提交或可靠用户操作为依据，排除 agent 自动续跑与工具事件。用户说 ChatGPT 时只用 ChatGPT 来源；缺少 ChatGPT 时间不能用 Codex 的夜间活动冒充。可采用 18:00—次日 06:00 的夜间窗口，午夜后按次日真实日期显示；不得把 23:59 机械判为比凌晨 01:00 更晚。保留时区、消息定位与短主题。不把最晚一条当作通宵、工作时长或生活习惯的证明。

## 项目投入与分类

只有总量或峰值、没有 ChatGPT 的项目和月份明细时，不得按消息数、活跃日或热力图颜色分摊 Token。可保留明确标注待补充的项目榜和月度格子，未知用量使用 null，不使用 0；聊天节奏可独立展示并注明单位与范围。最用心项目可按有证据的反复修改选为代表故事，但不能宣称真实情感或全账户用量排名。

用户要求 GPT 在生活中的身份时，根据可见的创作、学习和日常问答归纳角色，例如「创作搭档与日常答疑助手」。保留短依据，不展示健康、支付、家庭等私密细节，不推断依赖关系或把代写祝福当成用户对 GPT 的真实情感。

「最用心」不能直接测量。明确采用可核验 token 投入、主动活跃日或人工迭代次数中的哪一种代理指标，标题优先「记录中投入最多」。展示该项目去重用量、主动参与日期数及日历跨度；活跃 4 天、跨 5 个日历日不能改写为工作 5 天。自动审核量说明，不把它当成用户亲自投入。

共享聊天可能跨项目，按人类请求对应回合归属；找不到归属的标为未分配。多个版本、不同平台讨论同一作品，项目方向归组合并。项目类型按明确作品实体或已声明编辑归组数计算，一项一主类，分母显示在来源中；不以工具调用数、文件数或会话数代替项目数。

## 最常用模型

优先读取每次响应的真实 model ID。界面默认模型、最近配置与「auto / 均衡」路由标签不能证明真正模型。按有用量的有效响应记录数排名，或按 token 排名，并标明口径；能分别统计时同时保留两张排名。未知或路由未解析单列，不编造映射关系。系统自动审核单列，不进入用户常用模型榜。数据仅来自 Codex 与 WorkBuddy 时不能声称这是 ChatGPT 内最常用模型。

## 最后一屏

保留 4—6 项全年已覆盖数据：会话、用户输入、活跃日、token、项目方向、常用模型等。用一句 10—20 字画像和 2—3 个短标签收束，例如「有导演眼光的造物者」，旁边以已核验的修改、制作与分享行为支撑。呈现它是从记录归纳的年度画像，不做心理诊断、人格测评或超越人群的虚构排名。

## 可复用计算

```text
python <skill>/scripts/analyze_usage.py --codex-root <confirmed-codex-sessions> --workbuddy-root <confirmed-workbuddy-projects> --index <conversation-index.json> --project-map <project-map.json> --cutoff <collection-cutoff-ISO8601> --output <report-directory>
```

至少提供一个已确认的日志根。索引是一组 `{source_id,messages:[{id,at,locator}]}`；项目映射含 `threads`（完整 source_id → 项目 ID）、`message_overrides`（source_id/message_id → 项目 ID）与 `labels`（项目 ID → 展示名）。产出 `token-ledger.jsonl` 和 `usage-statistics.json`，仅含用量、模型、时间、项目与定位，不复制聊天正文。先查看 quality / failures 与未分配记录，确认累计值、分类和父子边界，再用于展示。
